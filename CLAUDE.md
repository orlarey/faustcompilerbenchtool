# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository Overview

This repository contains **Faust Compiler Benchmark Tools** - a suite of utilities designed to analyze and measure the performance of C++ code generated by the Faust compiler. The tools are used for developing new compilation strategies by ensuring correctness and evaluating performance impacts.

## Key Commands

### Installation

```bash
sudo ./install.sh
```
Installs all tools to `/usr/local/bin` and support files to `/usr/local/share/fctool`.

### Core Workflow
1. Generate C++ from Faust DSP file:
   ```bash
   faust foo.dsp -o foo.cpp
   ```
   For a whole directory at once:

   ```bash
   multifaust "-lang ocpp" dsp cppfiles
   ```

2. Benchmark performance (no privileges required):
   ```bash
   fcbenchtool foo.cpp
   ./foo
   ```

3. Repeated measurements with statistics:
   ```bash
   fcmultibench foo.cpp --runs 30 --format json --out foo.bench.json
   ```

4. Analyze generated code:
   ```bash
   fcanalyzetool foo.cpp  # Static analysis
   fcasmtool foo.cpp      # View assembly
   fcspilltool foo.cpp    # Register spill metrics for compute() (clang only)
   ```

### Python Tools
- **fcexplorer.py**: Explore compilation options
  ```bash
  fcexplorer.py -mcd "0 2 4 8" -vec "" foo.dsp
  ```
  Generates `foo_mcd_0.cpp`, `foo_mcd_0_vec.cpp`, etc.

- **fcbenchgraph.py**: Compare performance across configurations
  ```bash
  fcbenchgraph.py "*.dsp" "-lang cpp" "-lang cpp -vec" "-lang cpp -double"
  ```

- **fcanalyze.py**: Static analysis across configurations
  ```bash
  fcanalyze.py "*.dsp" "-lang cpp" "-lang cpp -vec"
  ```

- **fcoptimize.py**: Search for the best scalar compilation options for one DSP
  ```bash
  fcoptimize.py foo.dsp --lang ocpp --strategy adaptive --max-trials 200
  ```

- **fcspillgraph.py**: Compare register spills across configurations
  ```bash
  fcspillgraph.py "*.dsp" "-lang cpp" "-lang cpp -vec" --metric compute_stack
  ```

### Docker

A minimal image (`Dockerfile`) ships `fcbenchtool` + `fcmultibench` only, with
`fcmultibench` as the entrypoint:

```bash
docker build -t faust-bench-min .
docker run --rm -v "$PWD:/work" faust-bench-min /work/foo.cpp --runs 30
```

## Architecture

### Tool Structure
- **Shell Scripts** (`fc*tool`): Located in project root, these wrap C++ files with headers/footers and compile them
- **Python Scripts** (`*.py`): Automation tools for batch processing and analysis
- **Headers/Footers** (`*_header.cpp`, `*_footer.cpp`): Template code for wrapping Faust-generated C++

### Compilation Process

1. Tools wrap Faust-generated C++ between header and footer templates
   (`bencharch_*` for benchmarking, `plotarch_*` for everything else)
2. Compile with optimizations: `-O3 -ffast-math -fbracket-depth=1024 -march=native`
3. Resulting binaries measure performance or provide analysis

`fcbenchtool` allows overriding both flag groups: `FCBENCH_CXXFLAGS` replaces the
optimization flags, `FCBENCH_ARCH_FLAGS` replaces `-march=native`. On arm64 it
falls back to `-mcpu=native` if `-march=native` is rejected.

### Dependencies

- Faust compiler must be installed (`/usr/local/bin/faust`)
- C++ compiler (default: clang++, configurable via CXX environment variable)
- `fcspilltool`/`fcspillgraph.py` require clang specifically (`-fsave-optimization-record`); they refuse gcc
- Python 3 for automation scripts
- Optional: matplotlib for graph generation in fcbenchgraph.py, fcoptimize.py and fcspillgraph.py

## Development Notes

- Custom compiler can be specified: `CXX=clang++-19 fcbenchtool foo.cpp`
- Binary extensions can be customized for organizing different builds
- All tools follow similar pattern: process DSP → generate C++ → wrap with templates → compile → analyze/benchmark
- `install.sh` must list any new tool twice (the `cp` line and its `chmod`), plus a symlink for Python tools
